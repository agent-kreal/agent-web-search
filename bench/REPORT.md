# REPORT: какой поисковый провайдер под какой сценарий

Дата: 2026-08-27. Прогон: 32 запроса × 7 провайдеров (224 вызова, ~25 мин).
Датасет — дословные запросы из реальной истории сессий за 30.07–27.08
(~1150 запросов, см. `research-user-history.md`). Методика — `research-benchmarks.md`.

> **Публичная версия**: часть запросов датасета обезличена (нейтральные аналоги
> того же сценария), сырые прогоны `results/` (SERP-сниппеты, судейские
> материалы) не публикуются. Все числа ниже посчитаны на исходном полном наборе;
> воспроизвести — `run_bench.py` по `dataset.jsonl`.

**Это отчёт и рекомендации. Никакие изменения в тул/скилл не вносились.**

## 1. Резюме в пять строк

1. По качеству топ-3 два лидера с большим отрывом: **exa (1.53/2)** и **youcom (1.51/2,
   hit@3 94% — самый стабильный)**. Пачка середняков: tavily 1.42, brave 1.40,
   parallel-anon 1.32. **linkup 1.11 — значимо худший** (разрыв 0.2+ при N=32).
2. Сценарные лидеры: **code-docs и semantic → exa** (единственный прошёл проверку
   «отдай официальную доку playwright.dev»); **exact-fact → youcom/exa**;
   **ru-news → tavily**; **local-ru → youcom/brave** (tavily срезается: тащит EN-списки
   на RU-запрос); **debug-errors → tavily** (все слабы, 1.0–1.3).
3. **Оператор `site:`** соблюдают tavily/youcom/brave/linkup; parallel-anon игнорирует,
   exa на нём упал (единственный полный отказ в бенче).
4. **Операционно**: brave самый быстрый (медиана 1.4 с); linkup самый медленный
   (p90 7.1 с, deep-режим двойной цены); свежесть нативно умеют brave/exa/youcom/tavily.
5. **ddg** — 30 из 32 вызовов убиты антиботом под серией; по решению владельца
   выкидываем в «самый-самый последний фоллбэк, когда всё в жизни закончилось».

## 2. Методика

- **Датасет**: 8 сценариев × 4 запроса (ru-general, ru-news, en-news, exact-fact,
  semantic, code-docs, local-ru, debug-errors) — все реальные из истории.
  News-запросы с `--freshness week|month` (как реально использовалось).
- **Прогон**: single-shot, 1 запрос = 1 вызов, топ-5, пин провайдера (`--provider X`,
  фолбэк отключён). Сырьё: `results/raw.jsonl` (192 валидных записи у 6 провайдеров).
- **Оценка**: два LLM-судьи (по 4 сценария), слепые к именам провайдеров в решении,
  шкала 0/1/2 на каждый сниппет топ-3 + hit@3 по золотым доменам
  (для exact-fact/code-docs — жёсткие: exa.ai, discogs.com, playwright.dev…;
  для обзорных — мягкие списки). Оценки: `results/scores_*.jsonl`.
- **Ограничения**: N=32 на провайдера → статистически различимы только разницы
  >15–20 п.п. (Wilson 95%); один судья-LLM на блок (не усреднение нескольких);
  новости датированы 14–27.08 (сезонный сдвиг неизбежен); zai не гонялся
  (исчерпан до 18.09), parallel-$ и youcom-keyed не гонялись ($-гранты).

## 4. Профили провайдеров

- **exa** — лучший на официальных доках, репо, issue, академии (единственный дал
  playwright.dev; arxiv+aclanthology в семантике; оба issue CPython). Слабости:
  дубли одного документа под разными URL, изредка скрейсер-зеркала (wpnews.pro
  вместо github), на `site:`-запросе вообще не вернул выдачу. Худший сценарий —
  debug-errors (1.08).
- **youcom** — hit@3 94% (16/16 в RU/news-блоке!): стабильнее всех, идеальные блоки
  на Discogs/Yandex OCR/wireguard, уважает `site:`, лучшая связка pypi+github на
  ренейме ddgs. Слабости: изредка пустые слоты (1 результат вместо 3). 100/день
  сгорают — по квотам его и так надо жечь рано.
- **tavily** — нет провалов, нет блеска: топ-1 идеален лишь в 44% (реже всех!),
  на RU-специфику тащит глобальные EN-списки («LLM API провайдеры Россия» —
  три EN-статьи без РФ-угла; Google Cloud Vision вместо Яндекс OCR). Лучший в
  ru-news (даты релизов прямо в сниппетах) и debug-errors.
- **brave** — самый быстрый (1.4 с), силен на RU-general и жёстких цитатах
  (enterprise-доки, Discogs). Грязный хвост: на русскоязычный news-factcheck —
  статьи по теме без искомого субъекта; QA-vendor SEO (autify/iproyal/browserstack)
  вместо официальных доков; worst-case en-news (0.92: на минорный OSS-релиз
  вернул три чужих продукта).
- **linkup** — системные проблемы: нерелевантные языки (словенская вакансия на
  RU-запрос), микро-СМИ-мусор, февральская статья про GLM-5 под запросом про 5.3,
  grokipedia вместо pypi. Иногда единственно доставал экзотику (keyless-лимит Jina
  20 RPM). Deep-режим = 2× цена + p90 7.1 с. Самый дорогой по CPU-времени ожидания.
- **parallel-anon** — бесплатный, рабочая лошадка fan-out, но: продуктовые лендинги
  вместо страниц с цифрами (hit формально есть — цифры нет), дубли домена,
  спам-инъекции в сниппетах («обучение вокалу в Йокогаме» внутри страницы вуза),
  игнорирует `site:`.

## 6. Рекомендации: сценарный роутинг

Текущая цепочка — чисто экономическая (квоты: возобновляемые → keyless → дно → гранты).
Качество предлагает коррекции ВНУТРИ дня, когда провайдер выбираем из нескольких
доступных. Никаких код-изменений не внесено — ниже варианты на решение.

### 6.1. Целевая таблица «сценарий → предпочтительный порядок»

| Сценарий агента | Признаки запроса | Порядок (качество) |
|---|---|---|
| Официальные доки/репо/pypi | имя библиотеки, «docs», «github», API-метод | **exa** → youcom → tavily |
| Семантика/исследование | «best practices», «vs», обзор, сравнение подходов | **exa** → youcom → brave |
| Точный факт (цена/лимит/версия) | «pricing», «rate limit», «free tier», номер версии | **youcom** → exa → brave |
| RU-новости | кириллица + свежесть | **tavily** → youcom → brave; НЕ linkup |
| EN-новости | англ. + свежесть | exa → linkup → tavily; brave — не первым |
| RU-специфика (рынок/орг/цены РФ) | кириллица + РФ-сущности | **youcom** → brave → tavily |
| Debug (строки ошибок, issue) | «error», «exception», трейсбек, кавычки-цитаты | **tavily** → youcom → brave; exa рискован |
| Оператор `site:` | `site:` в запросе | tavily/youcom/brave/linkup; НЕ parallel-anon, exa |
| RU-общий (без специфики) | кириллица, общий тон | tavily ≈ youcom ≈ brave (равны) |

Экономика никуда не девается: порядок выше — это порядок ВЫБОРА, когда есть квоты
у нескольких; при исчерпании верхних провайдеров цепочка провалится вниз как обычно.

### 6.2. Три варианта реализации (по возрастанию кода)

> **СТАТУС: ВНЕДРЕНО 27.08 (Б+В+Г)** — флаг `--intent` + автодетект
> (`engine/intent.py`, валидация 32/32 на этом датасете) + телеметрия
> `usage.jsonl` c командой `wsearch usage`. См. `docs/implementation-intent.md`.

- **А. Правила в SKILL.md** (0 строк кода): таблица выше — в скилл как указание
  агенту: «для доков/семантики добавляй `--provider exa`, для RU-новостей
  `--freshness` + tavily/youcom». Гибко, но зависит от дисциплины агента.
- **Б. Флаг `--intent`** (~30 строк): `wsearch search "..." --intent docs` — роутер
  переупорядочивает цепочку по таблице 6.1. Явно, тестируемо, не ломает дефолт.
- **В. Автодетект интента** (~60 строк): эвристики в роутере (кириллица → ru-интент;
  «error/exception/traceback» → debug; «pricing/tier/limit/цена» → fact; «site:» →
  операторный режим) + дефолтная цепочка без изменений. Прозрачно для агента,
  но «магия» должна быть задокументирована.

Моя рекомендация: **Б + В вместе** (флаг явно, автодетект — дефолт при отсутствии
флага), таблица 6.1 — единый источник правды в коде. Но это на решение владельца.

### 6.3. Точечные правки (не требуют интентов)

1. **ddg** → самый-самый последний (решение владельца, зафиксировано).
2. **linkup** → понизить на позицию ниже parallel-anon в SEARCH_CHAIN, пока качество
   не улучшится (его «большой бак» лучше жечь на fan-out `multi`, где качество
   сниппетов менее критично).
3. **zai** — 18.09 вернётся квота: прогнать его этим же бенчмарком
   (`python3 bench/run_bench.py --providers zai`) и вписать в матрицу.
4. **exa для `site:`** — если внедряем интенты: в операторном режиме exa в конец.
