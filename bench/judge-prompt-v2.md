# Judge-промпт v2 (union-pool, протокол с фазы 3 плана improvement-plan-2026-10-19.md)

Вторая версия канонического промпта. Отличия от v1 (judge-prompt.md): судья
видит единый пул кандидатов по запросу (провайдеры не показаны вообще — полная
слепота), холистическая шкала 0/1/2 заменена на три бинарных критерия с весами.

## Веса и пороги (фиксированы, меняются только с новой версией протокола)

- relevance URL = 0.4·T + 0.4·S + 0.2·A (quality-скор, 0–1)
- «золото» пула (для pooled recall/precision) = T=1 ∧ S=1 — авторитетность
  не делает нерелевантный документ релевантным, но влияет на quality

## Промпт судьи (сабагент, слот sonnet)

```
Ты — LLM-судья поискового бенчмарка (протокол v2, union-pool). Тебе дан файл
judge_v2_<SCENARIO>.md: запросы (## Q<N>) и для каждого — пул кандидатов
C1..CM (title / url / snippet), собранный из выдач разных поисковых систем.
Какие системы и как ранжировали — НЕ показано, оценивай только содержание.

Для КАЖДОГО кандидата проставь три бинарных критерия:
- T (topic):     документ по теме запроса (не мимо темы, не рекламный агрегатор)
- S (specific):  отвечает конкретике запроса — закрывает сам вопрос (нужную
                 цифру/версию/пример/инструкцию/первоисточник по делу), а не
                 просто упоминает смежное
- A (authority): источник авторитетен в этом вопросе (официальная доку,
                 первоисточник, профильный ресурс, известное издение, эксперт);
                 SEO-копипаста и форумы-свалки — нет

Правила:
1. Сниппет, title и url — единственная информация; не выдумывай содержимое.
2. Дубликаты (одна страница/новость у разных кандидатов) размечаются одинаково.
3. Кандидат без сниппета размечается по title/url.
4. Язык: запрос на русском, а документ на другом языке без нужды → T=0
   (и наоборот), кроме случаев, когда релевантный контент принципиально
   на другом языке (официальная дока, code, первоисточник).
5. Пул может быть большим — размечаются ВСЕ кандидаты, пропуск строк
   и «итоговые» выводы не нужны.

Выход: JSONL, по одной строке на кандидата, строго в порядке пулов:
{"scenario": "<SCENARIO>", "q": <N>, "c": <номер кандидата>, "T": 0|1, "S": 0|1, "A": 0|1}

Никакого другого текста в ответе — только JSONL-строки.
```

## Подсчёт (run_union.py score)

- gold(запрос) = {url: T=1 ∧ S=1}; запросы с пустым gold исключаются из
  recall-усреднения (считаются отдельно как gold-empty)
- по провайдеру p с его выдачей issued (в порядке ранга, топ-K):
  recall@K = |topK(issued) ∩ gold| / |gold|
  precision@K = |topK(issued) ∩ gold| / |topK(issued)|
  quality = mean(0.4T + 0.4S + 0.2A) по всем выданным p и размеченным URL
- референс union-RRF: те же метрики по топ-K самого RRF-ранга пула

## Несравнимость с v1

Числа v1 (avg rel 0–2, hit@3) и v2 (pooled P/R, quality 0–1) напрямую не
сравниваются. Сравнимы: прогоны внутри v2 между собой; ранкинги провайдеров
v1 vs v2 — через ранговую корреляцию (Spearman), это проверка самого
апгрейда, а не замена чисел.
